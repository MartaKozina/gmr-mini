## 1. CRUD actions — ✅ (fixed)

Both core item types now have all four operations, each ownership-checked against `ctx.session.user.id`:

- **`pets`** (`src/server/api/routers/pet.ts`): `create` (10-27), `update` (30-53, edits `weightKg`/`lifestyle`), `getAll` (55-60, Read), `delete` (62-77). Deleting a pet runs in a `db.transaction` that removes the pet's recipes first, then the pet — since `recipes.petId` is a required FK, this also prevents orphaned recipes rather than just satisfying the constraint.
- **`recipes`** (`src/server/api/routers/recipe.ts`): `create` (19-56, also re-validates the referenced `petId` belongs to the caller — a correct IDOR guard beyond the minimum bar), `getAll` (59-70, Read, joined with `pet`), `update` (72-100, edits `name`/`dailyMassGrams`/`days` — proportions and ingredient composition stay fixed to the calculator's save flow by design, not editable in place from the list view), `delete` (102-115).

**Verdict**: met — either item type alone now clears "all four exist... and act on persisted data."
